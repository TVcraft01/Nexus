# The last pass's four gaps, closed on the phone — 2026-10-10

Device: R5CX73XFGKW (Samsung SM-A256E, Android 16 / SDK 36), `adb` at
`~/Android/Sdk/platform-tools/adb`. PC: headless the whole run — no Nexus
window was started and no compositor configuration was written. Screenshots in
`docs/evidence/shots-20261010/` were taken with `adb exec-out screencap -p`
only.

## 1. Peer reachability — PASS

The phone had no reachable peer, which is why Files had never been verified on
it. The rehearsal peer plus the ADB reverse tunnel fixes that:

```
flutter test test/rehearsal_peer.dart        # x2, one process each
  peer-pc-a  "Rehearsal PC"    listens 0.0.0.0:51820
  peer-pc-b  "Rehearsal PC 2"  listens 0.0.0.0:51831

adb reverse tcp:51999 tcp:51820
adb reverse tcp:51998 tcp:51831

adb shell "am start -a android.intent.action.VIEW -d \
  'nexus://pair?address=127.0.0.1&port=51999&code=<peer A code>&expires=<now+4m>' \
  dev.nexus.nexus"
adb shell "am start -a android.intent.action.VIEW -d \
  'nexus://pair?address=127.0.0.1&port=51998&code=<peer B code>&expires=<now+4m>' \
  dev.nexus.nexus"
```

Logcat, `dev.nexus.nexus` (both peers, seconds apart):

```
18:43:19  NEXUS mesh: pairWith -> ok
18:43:19  NEXUS cable: automatic pairing succeeded
18:43:25  NEXUS mesh: pairWith -> ok
18:43:25  NEXUS cable: automatic pairing succeeded
```

Peer side, one line each — the code was matched, so the phone reached the
listener *through the tunnel*, not by discovery:

```
NEXUS mesh: pair-request <- goou4tt557c220n1qbudc3xiq65c6hdf (code matched)
```

And the supervisor's own verdict minutes later:

```
18:43:40  NexusSupervisor: peer peer-pc-a is up again (0s of silence before it answered)
18:50:35  NexusSupervisor: peer peer-pc-b is up again (0s of silence before it answered)
```

Two caveats, both mechanical and both about the rehearsal rig rather than the
product:

* The provisioning URI is the **cable** payload (`address`, `port`, `code`,
  `expires`), not the QR payload (`id`, `name`, `ip`). A QR-shaped URI is
  refused by `CablePairing.parseProvisioningUri`, and the app logs nothing at
  all for it — one earlier attempt of mine paired nothing for exactly that
  reason. The `expires` field is required, and the peer's code lives 5 minutes
  from its own start, so peers must be started immediately before pairing.
* The `&` in the URI must be quoted for the *phone's* shell (wrap the whole
  command, single-quote the URI) or `am` receives only the part before the
  first `&`.

## 2. Assistant greeting — centred

`lib/ui/assistant_view.dart`, `_emptyChat`: the greeting block moved from a
top-padded `ListView` to `LayoutBuilder` + `ConstrainedBox(minHeight: the
room)` + `Center` inside a scroll view, so it centres in the thread area and
still scrolls at 1.5× type instead of being clipped.

Measured on the phone screenshot (`01-assistant-greeting-centred.png`,
1080×2340): the greeting line occupies y 960–998 and the chip row ends at
~1255; the thread area runs from ~380 (below the header block) to ~1950 (the
composer). Block centre ≈1108 against area centre ≈1165 — within 4% of the
middle, where it used to start 431px down, level with the status lines.
`test/ui_layout_test.dart` pins it: `|gapAbove − gapBelow| < 6% of the thread
area`, and the block never crosses `composer.top`.

## 3. Devices graph — two rings, panned canvas, state said once

`lib/ui/devices_view.dart`:

* **Two rings.** Three peers around this device, the rest on a second ring a
  whole node box further out. The phone had four paired devices, so the outer
  ring was exercised for real: `03-devices-graph-2-online.png` shows three
  inner nodes and "Rehearsal PC 2" outside them, with two solid links, and the
  strip reading "2 of 4 devices reachable right now".
* **Pan/zoom.** The picture is an `InteractiveViewer` (`constrained: false`,
  `minScale: 0.6`, the control's own 2.5 max) whose canvas is at least the
  content's own bounds. `test/devices_states_test.dart` drives a real drag and
  a real two-finger pinch on the widget tree and measures that the canvas
  followed the finger and that a node travels further from the pinch centre
  afterwards. On the phone with four paired devices the canvas was not wider
  than the page (the inner radius is clamped to the page, and the single outer
  node sits below), so there was nothing to pan in that configuration — pan
  earns its keep at five or more devices, or once zoomed.
* **De-duplicated state.** With the graph drawn, a row says what the device
  *is* ("Linux"); the state words and the status dot stay on the picture,
  where they are. `04-devices-list-no-repeated-state.png` is the "YOUR
  DEVICES" list under the graph — name and platform only. Past twelve devices
  the graph gives way and the rows carry the state themselves, which the
  thirteen-device test pins.

`lib/ui/files_view.dart`. Everything below is a screenshot against

The thumbnails are real image data, not a type glyph: the badge.png row's
leading box on the phone holds 380 distinct colours whose top three —
(84,197,248), (1,87,155), (41,182,246) — are the same three, in the same
order, as the source `assets/tray_icon.png` the peer serves; the type glyph on
a PDF row holds 89 and none of them the source's. Decoding happens at the size
it is drawn at (`cacheWidth`), one fetch at a time, only for images the
listing reported under 3 MB.

**Storage line:** the honest subset only — "3 items · 2.8 KB" is what the
folder holds. A "used of total" bar is *not* implemented: the peer sends names
and sizes, never bytes free, and nothing in the protocol carries capacity, so
such a line would be a number the app made up.

### Not reproduced on the device

Swipe-to-reveal (Rename / Delete on a row) could not be triggered with
`adb shell input swipe` or a hand-written `input motionevent` stream: the
row's `_slide` never left 0 (measured — the leading icon stays at x 53–119
before, during and after a 3s drag). The same injection *does* scroll a
horizontal `Scrollable` in the same screen (the device chips row moved 39px),
so injection itself works and the difference is the row's own
`HorizontalDragGestureRecognizer`. The gesture is covered by
`test/files_view_test.dart`, which drives it with `WidgetTester`, but it
should be checked with a finger before being called verified.

## What this pass did not fix

* The mesh graph still cannot show *which pair of peers are talking to each
  other*: the links are all drawn from this device outward, so a cross-link
  between two peers has nowhere to go.
* Thumbnails are fetched per listing, not streamed or cached across runs: the
  cache is the app's temp directory and a second visit refetches.
* Multi-select has no "Select all", no range selection, and the batch verbs
  run one file at a time — a batch is a loop, not a single operation.
* Sort and view preferences are per-app, not per-device.
