Nexus requester-only walkthrough — loopback-alias smoke evidence
================================================================

What: tool/gui_walkthrough.sh --peer-loopback drives the REQUESTER-ONLY pair
path on one machine. It launches a local server under the run's own directory,
reads that server's pairing code from its window and its mesh port from its
log, then drives the requester through the sheet's manual "Enter a code" tab
(Devices -> Add device -> More ways to connect -> Enter a code from the other
device), typing the code, the address and the port. The requester reaches the
server on the loopback alias 127.0.0.2 — a different address from discovery's
127.0.0.1 — so it is the typed-address path that actually runs.

This proves the requester-only CODE PATH (the manual pairing flow plus the
fetch and sha256 verify) works end to end. It is NOT a real LAN test: the peer
is a second process on the same machine over loopback, not a second host. A
two-box run against a physical machine on the LAN remains unexercised.

Where: Omarchy (Arch-based, Hyprland 0.56.2, Wayland), Flutter 3.47.5 /
Dart 3.13.4. Run dir: /tmp/nexus_gui/20261005-022323. The server bound mesh
port 34175; the requester paired to 127.0.0.2:34175 with the server's own code.

Command: ./tool/gui_walkthrough.sh --no-build --peer-loopback
