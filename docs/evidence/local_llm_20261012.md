# A local model inside Nexus — 2026-10-12

Nexus had the assistant, the mesh, the voice, the files — and no model. Every
phrase the command layer did not understand ended at a teach card, and the one
brain seam that could answer (`LocalBrain`) expected an Ollama server that a
phone can never run. This is the pass that puts a model *inside* the app: real
inference, on the device, offline, no server, no cloud, no account.

## What was added

One dependency: [`llamadart`](https://pub.dev/packages/llamadart) 0.11.1
(MIT). It is a llama.cpp runtime for Dart/Flutter that fetches its native
libraries with a build hook from pinned releases
(`leehack/llamadart-native` tag `v0.5.0-2`, per-bundle sha256 checked by the
hook), so no C++ toolchain is needed and nothing is vendored into the tree. It
was chosen over `llama_cpp_dart` (stable line needs you to build and ship the
shared library yourself), `flutter_llama` (custom non-commercial license,
Android build fetches sources), and `lib_llama_cpp` (a façade around a local
HTTP server, heavier for an in-process brain). The app ships only its llama.cpp
runtime, not its LiteRT-LM runtime (`hooks.user_defines` in `pubspec.yaml`).

New files: `lib/core/llm.dart` (the model itself), `lib/core/local_model_brain.dart`
(the model as a brain the assistant already talks to), `test/llm_test.dart`
(the decisions, with a fake runtime), `test/llm_live_smoke.dart` (the real
thing, run by hand).

| --- | --- | --- |
| file | `qwen2.5-0.5b-instruct-q4_k_m.gguf` | `qwen2.5-1.5b-instruct-q4_k_m.gguf` |
| bytes | 491,400,032 (469 MB) | 1,117,320,736 (1.04 GiB) |
| sha256 | `74a4da8c…e2e7b93d7a9db` | `6a1a2eb6…8970e434e9407e` |
| url | `huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/resolve/9217f5db…/…` | `huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/resolve/91cad511…/…` |
| license | Apache-2.0 (Qwen) | Apache-2.0 (Qwen) |

Both URLs are pinned to a commit, not a branch, and the full sha256 lives in
`lib/core/llm.dart` (`kPhoneModel`, `kDesktopModel`). The hashes were verified
against the real downloads with `sha256sum` — both matched exactly.

Not bundled in the APK. First launch fetches the file (background, via
`warmUp`), verifies the sha256 *while it streams*, and renames `.part` → the
cached name only on a match; a truncated or swapped download is deleted, never
loaded. A question asked during that fetch is honestly unanswered rather than
parked behind minutes of download.

Which model a device runs: phones get 0.5B, desktops get 1.5B when the machine
really has 4 GB (`/proc/meminfo` — the same file on Android and Linux), 0.5B
when it does not or when memory cannot be read.

## How the assistant uses it

Nothing new was invented for routing, because the seam already existed: a
phrase the command layer does not understand raises the teach card
(`teach:…`), the conversation engine asks the brain, and the brain — now
`LocalModelBrain` — answers with a model running in this process. A phrase
Nexus *does* understand never reaches the model: `get report.pdf from my pc`
is still a file fetch, and even `hello` is still Nexus's own capability card.
The model is the fallthrough, not the front door.

Desktop (`LocalModelBrain`) and phone (`DistributedBrain(tiny: TinyBrain(llm: …))`)
both run the same [Llm]; a machine that also has Ollama keeps it as the
fallback for when the in-app model has nothing to say. A model that cannot
answer reports `reachable: false` and the classic teach flow stays — the brain
remains an upgrade, never a dependency.

## The phone

R5CX73XFGKW (SM-A256E, arm64). The APK was installed over the release app
without losing its data, which needed one thing beyond the build: signatures
must match, and a profile APK is debug-signed by Flutter while the installed
app is signed with the repo's own key. The scratch build in the verification
worktree signs its profile build with `nexus-release.jks` (a build-config
change made only there — the repo's gradle file is untouched), so
`pm install -r` succeeded and the package stayed debuggable for the push.

The 469 MB model was pushed into the app's own models directory over USB
(12.7 s, `run-as … cat > files/models/qwen2.5-0.5b-instruct-q4_k_m.gguf`,
491,400,032 bytes) — the same directory and file name the app's own downloader
writes. Getting it there any other way was not on the table: the phone had no
WiFi, and spending 469 MB of somebody's cellular data is not a test's call.

It loaded on-device and answered:

```
23:00:19.247  I flutter : LLM: CPU ready, ctx 2048, 4t
```

- *"why is the sky blue"* → a Done card with the scattering answer
  ([shots-llm-20261012/sky-blue.png](shots-llm-20261012/sky-blue.png))
- *"why do cats purr"* → a Done card **in airplane mode**, in the same thread
  ([shots-llm-20261012/cats-airplane.png](shots-llm-20261012/cats-airplane.png))
  — every radio off, no paired device reachable, WiFi already off before that

Both answers came from the phone's own model: the phone's brain asks the
in-process `Llm` first, no peer was reachable, no `BRAIN:` fallback line ever
fired, and this feature has exactly one network path — the model *download* —
which never ran on the phone because the file was already cached. Inference
itself is in-process and offline.

The answers are also the honest quality of a 0.5B model: fluent, confident,
and wrong in the details (it has the scattering wavelengths backwards; it says
purring comes from ear muscles). That is a small local model. The point stands
— the words were generated on the phone, with the network off.

One wording gap to fix: the phone's status line still reads "Brain: your PC
(via mesh)" while the phone is answering with its own model. The line's
`viaMesh` check only asks whether the brain is a `DistributedBrain`, which is
true on Android whether or not a peer exists. It is a one-line change in
`assistant_view.dart` — deliberately not made here, because that file
currently holds parked mesh-memory work.

## Honest limits

- No streaming into the UI yet: the card appears when the answer is complete.
- The model answers; it does not act. It is told to point at real commands
  rather than invent actions, and nothing parses its words into commands.
- One model per device, chosen by platform and memory; no switching, no
  downloading the other size on demand.
- 0.5B is a small model: good for conversation and simple questions, not a
  knowledge base. The 1.5B is the desktop's; it is still small.
- Windows and macOS report no memory to us, so they get the 0.5B.
- First launch needs the network once (the download). Inference itself never
  does — proven on the phone in airplane mode.
